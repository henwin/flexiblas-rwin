# flexiblas-rwin

Experiments towards runtime-switchable BLAS/LAPACK for R on Windows through FlexiBLAS.

Everything follows the R-core Windows build. `docker/Dockerfile` checks out the R MXE tree for Rtools45 (R-dev SVN, `ucrt3/toolchain_libs/mxe`) at the revision that produced Rtools45 and sets it up from the pre-built CRAN toolchain tarballs, as the R-core howto describes. `scripts/build-mxe.sh` applies `patches/rtools-mxe/`, which updates `openblas.mk` to 0.3.34 with a fixed `NUM_THREADS`, adds `patches/openblas/` under the MXE names, and rebuilds OpenBLAS, as R-core would rebuild the toolchain. `scripts/build-bundle.sh` then builds the FlexiBLAS bundle with `patches/r-dev-web/flexiblas_bundle/`, scripts modelled on the R-core `tcl_bundle`, which builds the Tcl/Tk bundle that R ships. `bash scripts/build-in-docker.sh` runs both in the container and leaves the bundle in `dist/FlexiBLAS` and `dist/FlexiBLAS.zip`; the same command runs locally, in WSL and in GitHub Actions. The target is an argument, `x86_64` by default or `aarch64`, which cross-builds with the R-core LLVM toolchain in a second MXE tree into `dist/FlexiBLAS-aarch64`.

The bundle has the R layout: the DLLs in `bin/x64` (`bin` on aarch64), the OpenBLAS backends in `bin/x64/flexiblas`, `OPENBLAS-OPENMP` from the Rtools build and `OPENBLAS-THREADS` built by the bundle with pthreads, named as on Fedora, and the configuration in `etc`, with `NETLIB` as the default so that results are those of R's own BLAS and LAPACK. R uses it as it uses the Tcl/Tk bundle: unpacked as `R_HOME/FlexiBLAS` in the source tree and built with `USE_FLEXIBLAS = YES` (`patches/r/`), the R build makes `Rblas.dll` and `Rlapack.dll` export the import thunks of `libflexiblas.dll`, so that their entry points pass on to it and copies the bundle into `bin` and `etc`, from where the installer takes it. All BLAS and LAPACK calls in R therefore go through one FlexiBLAS instance.

The patches are kept by destination, each in one place. `patches/openblas/` and `patches/flexiblas/` are the upstream patches, `patches/openblas/0004` a commit of OpenBLAS after 0.3.34, backported; the build scripts put them where Rtools (`src/openblas-N-*.patch`) and the bundle (`flexiblas.diff`, as `tcl_bundle` has `tcl.diff`) expect them, and the submissions will be made the same way. `patches/rtools-mxe/` is the change to `openblas.mk`; `patches/r-dev-web/` holds the changes to the R-core Windows build scripts and howtos, as patches relative to `WindowsBuilds/` with one patch per submission, and the FlexiBLAS bundle; `patches/r/` holds the changes to R itself; `patches/r-flexiblas/` is the Windows support for the R package.

`build-bundle.yml` builds the bundle on `ubuntu-24.04` and tests it on `windows-2025`, for x86_64 only while aarch64 is paused: every backend loaded through `libflexiblas.dll` (`tests/load-backends.c`), and the thread-count cases behind `patches/openblas/` (`tests/omp-cases.sh`) against its `OPENBLAS-OPENMP` backend. That backend has its own static libgomp on x86_64 and does not see a caller's parallel region, so `patches/openblas/0004` takes no effect there; the case of calls from a parallel region checks that they neither hang nor mix their results. `build-r.yml` then builds R-devel, R-patched or R-release and its installer on `windows-2025` with the R-core `setup.ps1` and `build.sh` from R-dev-web, patched by `patches/r-dev-web/`, at the svn revision of the CRAN build of the same R (for release, that of its tag), checks that every patch of `patches/r` is in the tree, and runs `make check-devel` and `make check-all`. Its test job installs R from the installer and takes the CRAN build as the reference: the two must be the same revision, `Rblas.dll` and `Rlapack.dll` must export what CRAN's do less four LAPACK names nothing uses (`tests/compare-exports.sh`), every backend must give the R error message for an invalid argument (`tests/test-xerbla.R`), and `R CMD check` of seven packages, run twice under the reference and once under the built R, must give no NOTE, WARNING or ERROR and no line of example or test output that the reference does not, apart from what varies between the two reference runs and three differences by design (`tests/check-packages.sh`, `tests/compare-output.R`, with `tools::Rdiff`). It also installs the patched flexiblas package and runs the other tests in `tests/`.

The `o3-*` workflows are the evidence for building `Rblas.dll` with `-O3`, each with its tests in `tests/`: `o3-routines.yml` compares every routine of the R BLAS bit for bit between compiler flags; `o3-dlls.yml` does the same for whole `Rblas.dll` and `Rlapack.dll` builds in R, with timings; `o3-packages.yml` runs the examples and tests of the recommended and CRAN packages with the CRAN `Rblas.dll` and one built with `-O3`, under R-devel or R-release as CRAN builds them; `o3-probe.yml` does that for one package in detail. `nan-platforms.yml` compares how NA, NaN and Inf come out between FlexiBLAS backends, Accelerate, and the CRAN R on five platforms. Every workflow writes the result of its latest run as a comment on [issue #1](https://github.com/henwin/flexiblas-rwin/issues/1), one comment per workflow and variant.
