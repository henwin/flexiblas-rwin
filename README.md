# flexiblas-rwin

Experiments towards runtime-switchable BLAS/LAPACK for R on Windows through FlexiBLAS.

Everything follows the R-core Windows build. `docker/Dockerfile` checks out the R MXE tree for Rtools45 (R-dev SVN, `ucrt3/toolchain_libs/mxe`) at the revision that produced Rtools45 and sets it up from the pre-built CRAN toolchain tarballs, as the R-core howto describes. `scripts/build-mxe.sh` applies `patches/rtools-mxe/`, which updates `openblas.mk` to 0.3.34 with a fixed `NUM_THREADS`, adds `patches/openblas/` under the MXE names, and rebuilds OpenBLAS, as R-core would rebuild the toolchain. `scripts/build-bundle.sh` then builds the FlexiBLAS bundle with `patches/r-dev-web/flexiblas_bundle/`, scripts modelled on the R-core `tcl_bundle`, which builds the Tcl/Tk bundle that R ships. `bash scripts/build-in-docker.sh` runs both in the container and leaves the bundle in `dist/FlexiBLAS` and `dist/FlexiBLAS.zip`; the same command runs locally, in WSL and in GitHub Actions. The target is an argument, `x86_64` by default or `aarch64`, which cross-builds with the R-core LLVM toolchain in a second MXE tree into `dist/FlexiBLAS-aarch64`.

The bundle has the R layout: the DLLs in `bin/x64` (`bin` on aarch64), the OpenBLAS backends in `bin/x64/flexiblas`, the Rtools build with OpenMP and one the bundle builds with pthreads, and the configuration in `etc`. R uses it as it uses the Tcl/Tk bundle: unpacked as `R_HOME/FlexiBLAS` in the source tree and built with `USE_FLEXIBLAS = YES` (`patches/r/`), the R build makes `Rblas.dll` and `Rlapack.dll` forward to `libflexiblas.dll` and copies the bundle into `bin` and `etc`, from where the installer takes it. All BLAS and LAPACK calls in R therefore go through one FlexiBLAS instance.

The patches are kept by destination, each in one place. `patches/openblas/` and `patches/flexiblas/` are the upstream patches; the build scripts put them where Rtools (`src/openblas-N-*.patch`) and the bundle (`flexiblas.diff`, as `tcl_bundle` has `tcl.diff`) expect them, and the submissions will be made the same way. `patches/rtools-mxe/` is the change to `openblas.mk`; `patches/r-dev-web/` holds changes and additions to the R-core Windows build scripts, the FlexiBLAS bundle included; `patches/r/` holds the changes to R itself; `patches/r-flexiblas/` is the Windows support for the R package.

`build-bundle.yml` builds the bundle for both targets on `ubuntu-24.04` and runs the thread-count cases behind `patches/openblas/` (`tests/omp-cases.sh`) against its OpenBLAS backend on Windows. `build-r.yml` then builds R-devel or R-patched and its installer on `windows-2025` with the R-core `setup.ps1` and `build.sh` from R-dev-web, patched by `patches/r-dev-web/0002` to `0004`, runs `make check-devel` and `make check-all`, installs R from the installer, installs the patched flexiblas package and runs the tests in `tests/` against it, with the CRAN build of the same R for reference results.

The `o3-*` workflows are the evidence for building `Rblas.dll` with `-O3`, each with its tests in `tests/`: `o3-routines.yml` compares every routine of the R BLAS bit for bit between compiler flags; `o3-dlls.yml` does the same for whole `Rblas.dll` and `Rlapack.dll` builds in R, with timings; `o3-packages.yml` runs the R tests and the tests of CRAN packages with the CRAN `Rblas.dll` and one built with `-O3`, under R-devel or R-release as CRAN builds them; `o3-probe.yml` does that for one package in detail. `nan-platforms.yml` compares how NA, NaN and Inf come out between FlexiBLAS backends, Accelerate, and the CRAN R on five platforms. Every workflow writes the result of its latest run as a comment on [issue #1](https://github.com/henwin/flexiblas-rwin/issues/1), one comment per workflow.
