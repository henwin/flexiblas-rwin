# flexiblas-rwin

Experiments towards runtime-switchable BLAS/LAPACK for R on Windows through FlexiBLAS.

Everything follows R-core's own Windows build. `docker/Dockerfile` checks out R's MXE tree for Rtools45 (R-dev SVN, `ucrt3/toolchain_libs/mxe`) at the revision that produced Rtools45 and sets it up from CRAN's pre-built toolchain tarballs, as R-core's howto describes. `scripts/build-mxe.sh` applies `patches/rtools-mxe/`, which updates `openblas.mk` to 0.3.34 with a fixed `NUM_THREADS`, adds `patches/openblas/` under MXE's names, and rebuilds OpenBLAS, as R-core would rebuild the toolchain. `scripts/build-bundle.sh` then builds the FlexiBLAS bundle with `patches/r-dev-web/flexiblas_bundle/`, scripts modelled on R-core's `tcl_bundle`, which builds the Tcl/Tk bundle that R ships. `bash scripts/build-in-docker.sh` runs both in the container and leaves the bundle in `dist/FlexiBLAS` and `dist/FlexiBLAS.zip`; the same command runs locally, in WSL and in GitHub Actions.

The bundle has R's layout: the DLLs in `bin/x64`, the OpenBLAS backend in `bin/x64/flexiblas`, and the configuration in `etc`. R uses it as it uses the Tcl/Tk bundle: unpacked as `R_HOME/FlexiBLAS` in the source tree and built with `USE_FLEXIBLAS = YES` (`patches/r/`), R's build makes `Rblas.dll` and `Rlapack.dll` forward to `libflexiblas.dll` and copies the bundle into `bin` and `etc`, from where the installer takes it. All BLAS and LAPACK calls in R therefore go through one FlexiBLAS instance.

The patches are kept by destination, each in one place. `patches/openblas/` and `patches/flexiblas/` are the upstream patches; the build scripts put them where Rtools (`src/openblas-N-*.patch`) and the bundle (`flexiblas.diff`, as `tcl_bundle` has `tcl.diff`) expect them, and the submissions will be made the same way. `patches/rtools-mxe/` is the change to `openblas.mk`; `patches/r-dev-web/` holds changes and additions to R-core's Windows build scripts, the FlexiBLAS bundle included; `patches/r/` holds the changes to R itself; `patches/r-flexiblas/` is the Windows support for the R package.

`build-test.yml` builds the bundle on `ubuntu-24.04`. `rcore-build.yml` then builds R-devel and its installer on `windows-2025` with R-core's own `setup.ps1` and `build.sh` from R-dev-web, patched by `patches/r-dev-web/0002` to `0004`, runs `make check-devel` and `make check-all`, installs R from the installer, installs the patched flexiblas package and runs the tests in `tests/` against it, with CRAN's R-devel for reference results.

The other workflows are the evidence behind the patches and the proposals, each with its tests in `tests/`: `blas-bitwise.yml` compares every routine of R's BLAS bit for bit between compiler flags; `flags-timing.yml` does the same for whole `Rblas.dll` and `Rlapack.dll` builds in R, with timings; `cran-blas.yml` runs R's own tests and the tests of CRAN packages with CRAN's `Rblas.dll` and one built with `-O3`, and `rblas-probe.yml` does that for one package in detail; `nan-platforms.yml` compares how NA, NaN and Inf come out between FlexiBLAS backends, Accelerate, and CRAN's R on five platforms. `tests/omp-team.c` and `tests/omp-nested.c` run the thread-count cases behind `patches/openblas/` against a `libopenblas.so`.
